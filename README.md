# Irodori AutoSpeak

話題を投げると、SearXNGで調べ、LM StudioのLLMで喋る文章を作り、Irodori-TTSで音声にして、
途切れずに喋り続けるツール。喋っている最中に新しい話題を投げると、そちらに乗り換える。

**ゼロから環境を作る手順は [SETUP.md](SETUP.md) にあります。**

## 起動

```bash
./run.sh                 # 1台完結: TTSサーバー2つ + WebUI（既定）
./run.sh --webui-only    # WebUIだけ。TTSは別マシン
./run.sh --tts-only      # TTSサーバーだけ。WebUIは別マシン
```

既定は `.env` の `AUTOSPEAK_MODE=all|webui|tts` でも指定できる（オプションが優先）。
WebUIは http://localhost:8000。初回はモデルのダウンロードとロードで2〜3分かかる。
以降は20秒ほど。TTSサーバーだけ止めたいときは `./stop_tts.sh`。

`--webui-only` では TTS の接続先が未設定だと起動を止める。空のままだと `127.0.0.1` を
見にいって何も無い、という分かりにくい失敗になるため。TTS本体の取得（1.3GB）も行わない。

**Irodori-TTS-Server はこのリポジトリに同梱していない。** 初回の `run.sh` が
`vendor/Irodori-TTS-Server` へcloneして依存を入れる。独立したgitリポジトリのままなので、
本家の更新は `git -C vendor/Irodori-TTS-Server pull` で取り込める。

## 構成

| 役割 | ホスト | 備考 |
|---|---|---|
| WebUI / オーケストレータ / TTSワーカー | MacBook Pro `192.168.1.12` | このリポジトリ |
| LLM (LM Studio) | Mac Studio `192.168.1.11:1234` | **専用**。TTSと同居させない |
| 検索 (SearXNG) | Ubuntu `192.168.1.10:10000` | `format=json` 対応済み |

`192.168.1.11` にTTSも載せると、ユニファイドメモリを食い合ってスワップし、
1文の合成が100秒を超えることがある。LLMとTTSは必ず別のMacに置く。

ポートは `.env` で変えられる。シェルスクリプトとPython側が同じ `.env` を読むので、
書き換えるだけで `run.sh` / `start_tts.sh` / `stop_tts.sh` すべてが追従する。

```
AUTOSPEAK_PORT=8000              # WebUI
AUTOSPEAK_TTS_REF_PORT=8088      # 参照音声クローン
AUTOSPEAK_TTS_CAPTION_PORT=8089  # VoiceDesign
```

TTSワーカーを他のMacにも分散させたいときだけURLを明示する（ポート設定より優先される）:

```
AUTOSPEAK_TTS_REF_URLS=http://127.0.0.1:8088,http://192.168.1.13:8088
```

1台運用にしたい場合は `AUTOSPEAK_LLM_URL` をローカルに向けるが、そのときは
**小さめのLLMを使うこと**（上記のメモリ問題に当たる）。

## 動作の流れ

```
話題入力
  ↓
サブトピック決定 (LLM)         ← 2ターン目以降。既出の切り口は避ける
  ↓
SearXNG検索 → 上位3件の本文抽出   ← 話題の1ターン目はスキップ（発話開始を早めるため）
  ↓
LLMがストリーミング生成
  ↓ 句点を検出した瞬間に1文を切り出してTTSへ  ★全文を待たない
TTSワーカープール (エンドポイント数だけ並列)
  ↓
再生キュー（必ず元の順序で配信）
  ↓
ブラウザが順次再生・次を先読みロード
```

先読みは `PREFETCH_TURNS` ターンぶん、または `PREFETCH_SECONDS` 秒ぶんの未再生音声が
たまるまで進む。話題を割り込ませると、**再生中のターンは最後まで流し、それ以降は
音声が生成済みでも破棄する**。捨てた計算は無駄になるが、反応が約1ターンで済む。

## 話者

**1人モード**と、**2人が交互に喋るモード**がある。2人モードでは相手の直前の発言が
プロンプトに渡るので、相手の話を受けて返す形になる。話者ごとに声とペルソナを別々に
設定でき、片方を参照音声・もう片方をテキスト指定の声にすることもできる（その場合は
2つのTTSサーバーが同時に使われる）。

参照音声はWebUIの「参照音声の管理」からアップロード・削除できる。wav・flac以外は
自動でwavに変換される（macOSでは `afconvert`、Linuxでは `ffmpeg`）。音声はTTSサーバーの
voice APIで登録されるので、TTSが別マシンにいても動く。voice_idはASCIIのみという
TTSサーバー側の制約があり、日本語のファイル名は `voice_1a2b3c` のようなIDに変換される。

WebUIはモデルもGPUも使わないHTTPクライアントなので、**別マシンのDockerで動かせる**。
一式は [docker/](docker/) にある。

## TTSサーバー

接続先はWebUIの「設定 → TTSサーバー」で編集する。URLを入れて「接続」を押すと、
相手がどのチェックポイントを読んでいるかを取得して種別（参照音声 / テキスト指定）を
自動で埋める。**それぞれ別のマシンでよい**（Mac Studioに1つ、MacBookに1つ、など）。

- **2台構成** — 参照音声用とテキスト指定用が揃うので、2人交互モードが使える
- **1台構成** — チェックポイントは1つしか持てないので、**話者は1人に固定**される。
  UIの話者モードも自動でロックされる

**2つのTTSを同じMacで動かすと遅くなる。** 片方が合成していなくてもメモリとGPUを取り合うため、
実測で RTF 0.73 → 0.88（約17%悪化）。2人モードを常用するなら、2台目は別のMacに置くのが望ましい。

`.env` の `AUTOSPEAK_TTS_REF_URLS` / `AUTOSPEAK_TTS_CAPTION_URLS` は**初回のみ**
一覧の初期値として使われる。以降は `settings.local.json` が優先される。

## 設定

`.env`（URL類・ディレクトリ。起動時にのみ読む）と WebUIの設定パネル（実行中に変更可、
`settings.local.json` に保存され再起動しても残る）。

主なもの:

- **話者モード** — 1人 / 2人交互
- **声の指定方法**（話者ごと）— 参照音声クローン (`:8088`) か、テキストで声を説明する
  VoiceDesign (`:8089`)
- **ペルソナ**（話者ごと）— 口調と性格
- **num_steps** — 24が最適点。M1 Maxでの実測（RTFが1.0未満なら喋る速さより速く作れている）:

  | チェックポイント | steps | 1文あたり | RTF |
  |---|---|---|---|
  | 500M-v3（参照音声） | 40 | 4.69s | 0.98 |
  | 500M-v3（参照音声） | **24** | **2.83s** | **0.56** |
  | 500M-v3（参照音声） | 16 | 2.36s | 0.46 |
  | 600M-VoiceDesign（テキスト声） | 24 | 3.52s | 0.82 |
  | 600M-VoiceDesign（テキスト声） | 16 | 1.84s | 0.43 |

  VoiceDesign側はモデルが大きいぶん余裕が少ない。テキスト声モードで詰まるようなら
  num_stepsを16に下げるか、TTSワーカーを1台足す。
- **先読みターン / 秒数** — 深いほど途切れにくく、割り込みの反応が鈍る。

## ログ

`logs/session-<日時>.jsonl` に、喋った内容・切り口・参照URL・破棄されたかどうかを1ターン1行で追記する。

## 参照音声の取り扱い

このツールは参照音声から声を複製する。**自分が権利を持っている音声か、本人から許諾を得た
音声だけを使うこと。** 他人の声を無断で複製して公開・配信する行為は、法的にも倫理的にも
問題になりうる。ツール側で用途を判別する手段はないので、利用者の責任になる。

`voices/` は `.gitignore` に入れてある。参照音声はリポジトリにコミットしないこと。

## 検証用スクリプト

```bash
./.venv/bin/python bench_tts.py --voice <voice_id> --steps 40,24,16   # 合成速度の計測
./.venv/bin/python e2e_test.py --topic "話題" --switch-to "別の話題" --switch-after 90
```

`e2e_test.py` はブラウザの再生挙動を模擬して、無音が何秒生じたかを報告する。
